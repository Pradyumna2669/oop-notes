01

Introduction to OOP & Java

What OOP is, why it exists, and how Java actually runs your code.

1. Procedure-Oriented vs Object-Oriented Programming

Procedure-Oriented Programming (POP) structures a program as a list of procedures (functions) that operate on data. Object-Oriented Programming (OOP) structures a program around objects that bundle data and the functions that work on that data together.

POP — How It Thinks

  • Program = a sequence of functions called one after another.
  • Data moves openly between functions (mostly global).
  • Focus is on "what steps to perform".
  • Examples: C, Pascal, FORTRAN.

OOP — How It Thinks

  • Program = a set of objects that talk to each other.
  • Data is hidden inside objects (encapsulation).
  • Focus is on "which objects exist and what they do".
  • Examples: Java, C++, Python, C#.

POP vs OOP — Comparison

FeatureProcedure-OrientedObject-Oriented
Basic unitFunction / procedureObject & class
ApproachTop-downBottom-up
Data accessData is mostly global, freely accessibleData is hidden inside objects
Data securityLow — data exposed to all functionsHigh — controlled by access modifiers
ReusabilityLimitedHigh (inheritance)
Real-world modellingPoorExcellent
Example languagesC, PascalJava, C++, Python
🎯
Exam Tip
Remember the one-line difference: POP gives importance to functions; OOP gives importance to data (objects).

2. Introduction to OOP

Object-Oriented Programming (OOP) is a programming paradigm based on the concept of objects — real-world entities that have a state (data/fields) and behavior (methods/functions).

Two Core Building Blocks

Class

A blueprint or template. It defines what data and behavior its objects will have. E.g., Car.

Object

A real instance of a class — it occupies memory. E.g., myCar, yourCar.

Real-World Analogy

Think of a Car. Its state is colour, model, and speed. Its behavior is start, accelerate, and brake. A Car class describes that idea; each actual car you build from it is an object.

class Car {
    String color;            // state
    int speed;

    void accelerate() {       // behavior
        speed += 10;
        System.out.println("Speed: " + speed);
    }
}

class Test {
    public static void main(String[] args) {
        Car myCar = new Car();   // object created
        myCar.color = "Red";
        myCar.accelerate();           // Speed: 10
    }
}

3. Need of OOP

Procedure-oriented programs become hard to manage as they grow. OOP was created to solve those exact problems.

Problems with the Old Approach

  • Global data is unsafe — any function can change it.
  • Code is hard to reuse — you copy-paste functions.
  • Large programs become tangled and hard to debug.
  • It doesn't naturally model real-world entities.

How OOP Solves Them

NeedOOP Feature that Solves It
Protect data from misuseEncapsulation (data hiding)
Reuse existing codeInheritance
Hide complexity from the userAbstraction
One interface, many behaviorsPolymorphism
Model real-world thingsObjects & Classes
✓
In one line
OOP is needed because it makes large programs secure, reusable, modular, and easy to maintain.

4. Principles & Features of OOP

OOP stands on four pillars. Memorise them with the trick A-PIE: Abstraction, Polymorphism, Inheritance, Encapsulation.

The Four Pillars

1. Encapsulation

Wrapping data and methods into a single unit (class) and hiding the data using access modifiers.

2. Abstraction

Showing only essential features and hiding the internal details. E.g., you drive a car without knowing the engine internals.

3. Inheritance

One class acquires the properties of another. Enables code reuse. "Dog IS-A Animal".

4. Polymorphism

"Many forms" — the same method behaves differently for different objects (overloading & overriding).

Other Key Features of OOP

  • Class & Object — the fundamental units.
  • Message passing — objects communicate by calling methods.
  • Data security — through access modifiers (private, public, protected).
  • Reusability & extensibility — via inheritance.
🎯
Exam Tip
Always list the four pillars (A-PIE) with a one-line definition and a tiny example for each.

5. JDK, JVM & JRE

These three are the heart of how Java works. Understanding them is a guaranteed exam question.

JVM — Java Virtual Machine

The JVM is an abstract machine that runs Java bytecode. It is the reason Java is platform-independent — "Write Once, Run Anywhere" (WORA).
  • Loads .class (bytecode) files.
  • Verifies the bytecode for security.
  • Converts bytecode into machine code and executes it.
  • The JVM is platform-dependent, but the bytecode it runs is platform-independent.

JRE — Java Runtime Environment

The JRE provides everything needed to run a Java program. It contains the JVM + core libraries, but no development tools.

JRE = JVM + Java Class Libraries. Use the JRE if you only want to run Java apps, not write them.

JDK — Java Development Kit

The JDK is the full toolkit to develop and run Java programs. It contains the JRE + development tools like the compiler (javac) and debugger.

JDK = JRE + Development Tools (javac, javadoc, jdb…)

6. Setting Up the Java Development Environment

Before writing Java, you need the JDK installed and the system configured to find it.

Steps

  1. Download the JDK from Oracle or adopt OpenJDK.
  2. Install it (note the install folder, e.g. C:\Program Files\Java\jdk-21).
  3. Set the PATH environment variable to the JDK's bin folder so javac works from any directory.
  4. (Optional) Set JAVA_HOME to the JDK root folder.
  5. Verify the installation from a terminal.

Verify Installation

> java -version
java version "21.0.1" 2023-10-17 LTS

> javac -version
javac 21.0.1
💡
PATH vs JAVA_HOME
PATH lets the OS find the java/javac commands. JAVA_HOME points tools (like build systems) to the JDK root folder.

You can write Java in any text editor (Notepad, VS Code) or a full IDE like IntelliJ IDEA, Eclipse, or NetBeans.

7. Structure of a Java Program

A typical Java program is organised into clear sections, from top to bottom:

  1. Documentation section — comments describing the program (optional).
  2. Package statement — declares the package (optional, first line if present).
  3. Import statements — bring in other classes.
  4. Class definition — the program lives inside a class.
  5. main() method — the entry point where execution begins.

Annotated Example

/* Documentation: My first Java program */

package mypack;            // (optional) package statement

import java.util.*;          // import statement

public class Hello {       // class definition

    // main method — program starts here
    public static void main(String[] args) {
        System.out.println("Hello, World!");
    }
}

Breaking Down main

PartMeaning
publicAccessible from anywhere — the JVM must call it.
staticRuns without creating an object of the class.
voidReturns nothing.
mainThe fixed name the JVM looks for as the entry point.
String[] argsReceives command-line arguments.
⚠
File-naming rule
A public class must be saved in a file with the exact same name — class Hello → file Hello.java.

8. Execution of a Simple Java Program

Java runs in two stages: first compile the source into bytecode, then run the bytecode on the JVM.

Step 1 — Compile

The compiler javac turns Hello.java (source) into Hello.class (bytecode).

> javac Hello.java     →   produces Hello.class

Step 2 — Run

The java command loads Hello.class into the JVM, which executes it.

> java Hello
Hello, World!

The Full Pipeline

  Hello.java          javac           Hello.class          JVM            Output
 (source code)  ───────────────▶   (bytecode)   ───────────────▶   "Hello, World!"
                  COMPILE TIME                       RUN TIME

  Platform-independent bytecode is the magic:
  the SAME Hello.class runs on Windows, Linux, or macOS
  because each OS has its own JVM.
🎯
Exam Tip
Two commands, two stages: javac = compile (source → bytecode), java = execute (bytecode → output). This two-step model is what makes Java portable.

Foundation of Java Programming

The raw materials: data types, operators, and control flow.

1. Data Types

A data type tells the compiler what kind of value a variable can hold and how much memory to reserve for it. Java is a strongly typed language — every variable must have a declared type.

Two Categories

Primitive (8 types)

Built-in, store actual values directly. byte, short, int, long, float, double, char, boolean.

Non-Primitive (Reference)

Refer to objects in memory. String, arrays, classes, interfaces.

The 8 Primitive Types

TypeSizeDefaultExample
byte1 byte0byte b = 100;
short2 bytes0short s = 5000;
int4 bytes0int i = 100000;
long8 bytes0Llong l = 99999999L;
float4 bytes0.0ffloat f = 5.75f;
double8 bytes0.0ddouble d = 19.99;
char2 bytes''char c = 'A';
boolean1 bitfalseboolean flag = true;

Example

class DataTypes {
    public static void main(String[] args) {
        int age = 21;
        double price = 99.99;
        char grade = 'A';
        boolean isPass = true;
        String name = "Stoic";        // non-primitive

        System.out.println(name + " | " + age + " | " + grade);
    }
}
💡
Note
long literals end with L and float literals end with f, because the defaults are int and double.

2. Type Conversion & Casting

Type conversion means converting a value from one data type to another. It happens in two ways: automatic (widening) and manual (narrowing / casting).

1. Widening (Implicit / Automatic)

  • Smaller type → larger type. Done automatically by Java.
  • No data loss. Safe.
  • Order: byte → short → int → long → float → double.
int i = 100;
double d = i;        // int → double, automatic
System.out.println(d); // 100.0

2. Narrowing (Explicit / Casting)

  • Larger type → smaller type. Must be done manually.
  • Possible data loss. You take responsibility with a cast.
double d = 9.78;
int i = (int) d;       // explicit cast, fraction lost
System.out.println(i);  // 9

Widening vs Narrowing

FeatureWideningNarrowing
DirectionSmall → LargeLarge → Small
Done byCompiler (automatic)Programmer (manual cast)
Data lossNoPossible
Cast operator needed?NoYes — (type)
🧠
Memory Trick
Widening is Worry-free. Narrowing needs a cast.

3. Operators

An operator is a symbol that performs an operation on one or more values (operands), such as +, -, ==, or &&.

Categories of Operators

CategoryOperatorsPurpose
Arithmetic+ - * / %Basic math
Relational== != > < >= <=Compare values → boolean
Logical&& || !Combine boolean conditions
Assignment= += -= *= /= %=Assign values
Unary++ -- + - !Act on a single operand
Bitwise& | ^ ~ << >>Bit-level operations
Ternary? :Shorthand if-else

Example

int a = 10, b = 3;

System.out.println(a + b);      // 13  arithmetic
System.out.println(a % b);      // 1   remainder
System.out.println(a > b);      // true  relational
System.out.println(a > 5 && b < 5); // true  logical

// ternary: condition ? valueIfTrue : valueIfFalse
String result = (a > b) ? "a wins" : "b wins";
System.out.println(result);     // a wins
💡
Pre vs Post increment
++a increments then uses the value; a++ uses the value then increments.

4. Precedence Rules & Associativity

Precedence decides which operator runs first when several appear in one expression. Associativity decides the direction (left-to-right or right-to-left) when operators have the same precedence.

Example of Precedence

int x = 2 + 3 * 4;     // * before + → 2 + 12 = 14
int y = (2 + 3) * 4;   // () forces + first → 20

5. Flow of Control — Conditional Statements

Conditional statements let a program make decisions and run different code based on whether a condition is true or false.

1. if / else-if / else

int marks = 75;

if (marks >= 90) {
    System.out.println("Grade A");
} else if (marks >= 60) {
    System.out.println("Grade B");
} else {
    System.out.println("Grade C");
}

2. switch

Chooses one block out of many based on a single value. Cleaner than a long if-else chain.

int day = 3;

switch (day) {
    case 1: System.out.println("Monday"); break;
    case 2: System.out.println("Tuesday"); break;
    case 3: System.out.println("Wednesday"); break;
    default: System.out.println("Other day");
}
⚠
Don't forget break
Without break, execution "falls through" into the next case. The default case handles unmatched values.

6. Flow of Control — Loops

A loop repeats a block of code as long as a condition stays true. Java has three main loops: for, while, and do-while.

1. for Loop

Best when you know how many times to repeat.

for (int i = 1; i <= 5; i++) {
    System.out.println("Count: " + i);
}

2. while Loop

Best when the number of repetitions is unknown. Condition checked before the body (entry-controlled).

int i = 1;
while (i <= 5) {
    System.out.println(i);
    i++;
}

3. do-while Loop

Runs the body at least once, because the condition is checked after the body (exit-controlled).

int i = 1;
do {
    System.out.println(i);
    i++;
} while (i <= 5);

Comparison

LoopCondition checkedMin runsUse when
forBefore0Count is known
whileBefore0Count is unknown
do-whileAfter1Must run at least once

Enhanced for (for-each)

int[] nums = {10, 20, 30};
for (int n : nums) {
    System.out.println(n);
}

7. Flow of Control — Branching Statements

Branching (jump) statements transfer control to another part of the program.

1. break

Immediately exits the nearest loop or switch.

for (int i = 1; i <= 10; i++) {
    if (i == 5) break;     // stops at 5
    System.out.println(i);   // 1 2 3 4
}

2. continue

Skips the rest of the current iteration and jumps to the next one.

for (int i = 1; i <= 5; i++) {
    if (i == 3) continue;  // skips 3
    System.out.println(i);   // 1 2 4 5
}

3. return

Exits the current method and optionally sends back a value.

static int square(int n) {
    return n * n;     // exits method, returns value
}

break vs continue

Featurebreakcontinue
EffectExits the loop entirelySkips to next iteration
Used inLoops & switchLoops only
03

Encapsulation

Classes, objects, constructors, and the tools that bundle data with behavior.

1. Classes & Objects

A class is a blueprint that defines fields (data) and methods (behavior). An object is a real instance of a class that occupies memory. Encapsulation is the wrapping of data and methods into this single unit.

Defining a Class & Creating Objects

class Student {
    // fields (state)
    String name;
    int roll;

    // method (behavior)
    void display() {
        System.out.println(roll + " - " + name);
    }
}

class Test {
    public static void main(String[] args) {
        Student s1 = new Student();  // object
        s1.name = "Stoic";
        s1.roll = 101;
        s1.display();                  // 101 - Stoic
    }
}

The new Keyword

new allocates memory for the object on the heap and returns a reference to it. Student s1 = new Student(); — s1 is the reference, the object lives on the heap.

Encapsulation in Practice (Data Hiding)

Make fields private and expose them through public getter/setter methods.

class Account {
    private double balance;   // hidden

    public void setBalance(double b) {
        if (b >= 0) balance = b;  // validation
    }
    public double getBalance() {
        return balance;
    }
}

2. Methods

A method is a block of code that performs a specific task and runs only when called. Methods give programs reusability and structure.

Anatomy of a Method

  public  int   add(int a, int b)  {  return a + b;  }
  ───┬──  ──┬─   ─┬─  ──────┬──────      ──────┬──────
  modifier  |   name    parameters          body
        return type

Example: Defining & Calling

class Calc {
    // method with parameters and a return value
    int add(int a, int b) {
        return a + b;
    }

    public static void main(String[] args) {
        Calc c = new Calc();
        int sum = c.add(5, 7);   // call
        System.out.println(sum);     // 12
    }
}

Method Types

  • Instance method — called on an object.
  • Static method — called on the class itself (Math.sqrt()).
  • Parameterized vs no-argument methods.

3. Constructors

A constructor is a special method that runs automatically when an object is created. It is used to initialise the object. It has the same name as the class and no return type.

Types of Constructors

Default

No parameters. Provided automatically by Java if you write none.

Parameterized

Takes arguments to set field values at creation time.

Copy

Creates a new object by copying another object's values.

Example

class Student {
    String name;
    int roll;

    // parameterized constructor
    Student(String n, int r) {
        name = n;
        roll = r;
    }

    void show() { System.out.println(roll + " " + name); }

    public static void main(String[] args) {
        Student s = new Student("Stoic", 101);
        s.show();   // 101 Stoic
    }
}

Constructor vs Method

FeatureConstructorMethod
NameSame as classAny valid name
Return typeNone (not even void)Must have one
CalledAutomatically on newExplicitly by name
PurposeInitialise objectPerform a task

4. this Keyword

The this keyword is a reference to the current object — the object whose method or constructor is being called.

Main Use: Resolve Naming Conflicts

When a parameter has the same name as a field, this distinguishes them.

class Student {
    String name;

    Student(String name) {
        this.name = name;   // this.name = field, name = parameter
    }
}

Other Uses of this

  • this.field — refer to the current object's field.
  • this.method() — call another method of the current object.
  • this(...) — call another constructor of the same class (constructor chaining).
  • Pass the current object as an argument: obj.process(this).

5. Garbage Collection

Garbage Collection (GC) is the automatic process by which the JVM reclaims memory occupied by objects that are no longer referenced (unreachable). Java handles memory cleanup for you — no manual free() as in C/C++.

When Does an Object Become Eligible?

  • Its reference is set to null.
  • The reference is reassigned to another object.
  • The object is created inside a method and the method ends (local scope).

Example

Student s1 = new Student();
s1 = null;        // old object now unreachable → eligible for GC

System.gc();       // REQUEST the JVM to run GC (not guaranteed)

Key Points

  • GC runs on a low-priority background thread.
  • System.gc() only requests collection — the JVM decides when.
  • The finalize() method was historically called before an object was collected (now deprecated).
  • Prevents most memory leaks automatically.
💡
Why it matters
Automatic GC is a big reason Java is safer and easier than C/C++ — you rarely manage memory by hand.

6. Arrays

An array is a container that holds a fixed number of values of the same type in contiguous memory. Array indices start at 0.

1. One-Dimensional Array

// declaration + initialization
int[] marks = {85, 90, 78, 92};

// using new + size
int[] nums = new int[5];   // 5 zeros
nums[0] = 10;

System.out.println(marks[1]);       // 90
System.out.println(marks.length);    // 4

Looping Through an Array

for (int i = 0; i < marks.length; i++) {
    System.out.println(marks[i]);
}

// for-each (enhanced for)
for (int m : marks) {
    System.out.println(m);
}

2. Two-Dimensional Array

int[][] matrix = {
    {1, 2, 3},
    {4, 5, 6}
};

System.out.println(matrix[1][2]);   // 6
⚠
Watch the bounds
Accessing an invalid index throws ArrayIndexOutOfBoundsException. Valid indices are 0 to length - 1.

7. Command Line Arguments

Command line arguments are values passed to a program when it is run, captured by the String[] args parameter of main.

Example

class CmdDemo {
    public static void main(String[] args) {
        System.out.println("Number of args: " + args.length);
        for (String a : args) {
            System.out.println(a);
        }
    }
}

Running It

> javac CmdDemo.java
> java CmdDemo Hello World 42

Number of args: 3
Hello
World
42
💡
Always Strings
Arguments arrive as Strings. To do math, convert first: int n = Integer.parseInt(args[0]);

8. Scanner Class

The Scanner class (in java.util) reads input from the user at runtime — from the keyboard, files, or strings.

Steps to Use Scanner

  1. import java.util.Scanner;
  2. Create an object: Scanner sc = new Scanner(System.in);
  3. Read input with methods like nextInt(), nextLine().
  4. Close it: sc.close();

Example

import java.util.Scanner;

class InputDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);

        System.out.print("Enter name: ");
        String name = sc.nextLine();

        System.out.print("Enter age: ");
        int age = sc.nextInt();

        System.out.println(name + " is " + age + " years old.");
        sc.close();
    }
}

Common Scanner Methods

MethodReads
nextInt()An int
nextDouble()A double
next()A single word (token)
nextLine()A whole line of text
nextBoolean()A boolean
⚠
The nextLine() trap
Calling nextLine() right after nextInt() reads the leftover newline. Add an extra sc.nextLine(); to consume it.

9. Enumerated Type (enum)

An enum is a special type that defines a fixed set of named constants. Use it when a variable should only hold one value from a known list — like days, directions, or states.

Basic Example

enum Day { MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY }

class Test {
    public static void main(String[] args) {
        Day today = Day.WEDNESDAY;
        System.out.println(today);          // WEDNESDAY

        switch (today) {
            case MONDAY:    System.out.println("Start of week"); break;
            case WEDNESDAY: System.out.println("Midweek");       break;
            default:        System.out.println("Some day");
        }
    }
}

Looping Over enum Values

for (Day d : Day.values()) {
    System.out.println(d);
}

Why Use enum?

  • Type safety — only valid constants can be assigned.
  • Readability — Day.MONDAY beats a magic number like 1.
  • Works cleanly with switch statements.
  • Useful methods: values() (all constants), ordinal() (position), name().
✓

04

Inheritance & Polymorphism

Reusing code, extending behavior, and writing flexible programs.

1. Inheritance & Its Types

Inheritance is a mechanism by which one class (called the child or subclass) acquires the fields and methods of another class (called the parent or superclass). It is one of the four pillars of OOP and the foundation of code reusability.

Why Inheritance?

  • Code reusability — write code once in the parent, reuse in many children.
  • Method overriding — gives the child the power to redefine parent behavior.
  • Models real-world relationships — "Dog IS-A Animal", "Car IS-A Vehicle".

Syntax

class Parent {
    // fields and methods
}

class Child extends Parent {
    // inherits everything from Parent
}

The 5 Types of Inheritance

1. Single

One subclass inherits from one superclass. A → B

2. Multilevel

Chain of inheritance. A → B → C

3. Hierarchical

Many children share one parent. A → B, A → C

4. Multiple

One class inherits from many. Not allowed via classes — use interfaces.

5. Hybrid

Combination of two or more types. Achieved via interfaces.

Diagrammatic View

Example: Single Inheritance

class Animal {
    void eat() { System.out.println("Eating..."); }
}

class Dog extends Animal {
    void bark() { System.out.println("Barking..."); }
}

class Test {
    public static void main(String[] args) {
        Dog d = new Dog();
        d.eat();   // inherited from Animal
        d.bark();  // own method
    }
}

Example: Multilevel Inheritance

class Animal { void eat() { System.out.println("Eating"); } }
class Dog    extends Animal { void bark() { System.out.println("Barking"); } }
class Puppy  extends Dog    { void weep() { System.out.println("Weeping"); } }

Example: Hierarchical Inheritance

class Animal {
    void eat() { System.out.println("Eating..."); }
}

class Dog extends Animal {
    void bark() { System.out.println("Barking..."); }
}

class Cat extends Animal {
    void meow() { System.out.println("Meowing..."); }
}

class Test {
    public static void main(String[] args) {
        Dog d = new Dog(); d.eat(); d.bark();
        Cat c = new Cat(); c.eat(); c.meow();
    }
}

Example: Multiple Inheritance (via Interfaces)

Java doesn't allow a class to extend multiple classes, but a class can implement multiple interfaces — that's how Java achieves multiple inheritance.

interface Father {
    void height();
}

interface Mother {
    void color();
}

// Child inherits from BOTH Father and Mother
class Child implements Father, Mother {
    public void height() { System.out.println("Tall like Father"); }
    public void color()  { System.out.println("Fair like Mother"); }
}

class Test {
    public static void main(String[] args) {
        Child c = new Child();
        c.height();   // Tall like Father
        c.color();    // Fair like Mother
    }
}

Example: Hybrid Inheritance (via Interfaces)

Hybrid = a mix of two or more types of inheritance. The example below combines hierarchical (one parent → multiple children) with multiple (one child → multiple parents).

// Base class (hierarchical part)
class Animal {
    void eat() { System.out.println("Eating..."); }
}

// Two children of Animal (hierarchical)
class Mammal extends Animal {
    void walk() { System.out.println("Walking..."); }
}

interface Bird {
    void fly();
}

// Bat behaves as both Mammal and Bird (multiple via interface)
class Bat extends Mammal implements Bird {
    public void fly() { System.out.println("Flying..."); }
}

class Test {
    public static void main(String[] args) {
        Bat b = new Bat();
        b.eat();    // from Animal
        b.walk();   // from Mammal
        b.fly();    // from Bird (interface)
    }
}
⚠
Why Java doesn't support Multiple Inheritance with classes
To avoid the Diamond Problem — ambiguity that arises when two parent classes have a method with the same signature. Java solves this elegantly using interfaces.

2. Method Overloading (Compile-Time Polymorphism)

Method Overloading means defining multiple methods with the same name in the same class but with different parameter lists (different number, type, or order of parameters).

Rules of Overloading

  • Method name must be the same.
  • Method parameter list must differ (count, type, or order).
  • Return type alone is NOT enough to overload a method.
  • Resolved at compile-time — also called static binding or early binding.

Why Use It?

  • Improves readability — same name for similar operations.
  • Lets methods perform similar tasks on different input types.

Example

class MathOps {
    // 1. Two integers
    int add(int a, int b)            { return a + b; }

    // 2. Two doubles (different type)
    double add(double a, double b)   { return a + b; }

    // 3. Three integers (different count)
    int add(int a, int b, int c)     { return a + b + c; }
}

class Test {
    public static void main(String[] args) {
        MathOps m = new MathOps();
        System.out.println(m.add(2, 3));         // 5
        System.out.println(m.add(2.5, 3.5));     // 6.0
        System.out.println(m.add(1, 2, 3));      // 6
    }
}
💡
Memory hook
"Same name, different signature" → Overloading.

3. Method Overriding (Run-Time Polymorphism)

Method Overriding means a subclass provides its own implementation of a method that is already defined in its parent class — using the same name, same parameters, and same return type.

Rules of Overriding

  • Method signature must be exactly the same as the parent.
  • Access modifier of child can be same or less restrictive, never more.
  • Final, static, and private methods cannot be overridden.
  • Resolved at runtime — also called dynamic binding or late binding.
  • Use the @Override annotation (optional but recommended for safety).

Example

class Animal {
    void sound() { System.out.println("Animal makes a sound"); }
}

class Dog extends Animal {
    @Override
    void sound() { System.out.println("Dog barks"); }
}

class Cat extends Animal {
    @Override
    void sound() { System.out.println("Cat meows"); }
}

class Test {
    public static void main(String[] args) {
        Animal a;
        a = new Dog(); a.sound();   // Dog barks
        a = new Cat(); a.sound();   // Cat meows
    }
}

This is dynamic method dispatch — the JVM decides at runtime which version of sound() to call based on the actual object type.

Overloading vs Overriding

Polymorphism typeCompile-timeRun-time
Inheritance needed?NoYes

4. Polymorphism — The Big Picture

Polymorphism means "many forms". In Java, it allows the same action (method call) to behave differently depending on the object that performs it.

Two Types

Compile-Time

Achieved by Method Overloading. The compiler decides which method to call.

Run-Time

Achieved by Method Overriding. The JVM decides at runtime based on the actual object.

Why is Polymorphism Useful?

  • Flexibility — write code that works with parent types but executes child behavior.
  • Extensibility — add new subclasses without changing existing code.
  • Cleaner design — fewer if-else chains.

5. Interfaces

An interface is a 100% abstract type — a "contract" that lists method signatures but provides no implementation. Any class that implements the interface promises to define all of its methods.

Why Interfaces?

  • Achieve full abstraction.
  • Enable multiple inheritance in Java.
  • Define contracts that classes must follow.
  • Decouple "what to do" from "how to do it".

Syntax & Example

interface Drawable {
    void draw();   // abstract by default
}

class Circle implements Drawable {
    public void draw() { System.out.println("Drawing Circle"); }
}

class Rectangle implements Drawable {
    public void draw() { System.out.println("Drawing Rectangle"); }
}

Multiple Inheritance via Interfaces

interface Printable { void print(); }
interface Showable  { void show();  }

class Demo implements Printable, Showable {
    public void print() { System.out.println("Printing"); }
    public void show()  { System.out.println("Showing"); }
}

Key Points

  • All interface methods are public and abstract by default.
  • All variables are public static final (constants).
  • An interface cannot be instantiated directly.
  • A class can implement multiple interfaces.
  • From Java 8: interfaces can have default and static methods with bodies.

6. Abstract Class

An abstract class is a class declared with the abstract keyword. It cannot be instantiated and may contain both abstract methods (no body) and concrete methods (with body).

Why Use It?

  • Provide a partial implementation as a base for child classes.
  • Force subclasses to implement specific methods.
  • Share common code between related classes.

Example

abstract class Shape {
    abstract void draw();              // must be overridden
    void display() { System.out.println("Shape displayed"); }
}

class Rectangle extends Shape {
    void draw() { System.out.println("Drawing Rectangle"); }
}

class Test {
    public static void main(String[] args) {
        Shape s = new Rectangle();
        s.draw();
        s.display();
    }
}

7. super Keyword

The super keyword refers to the immediate parent class. It is used to access parent class members (variables, methods, constructors) from within a child class.

Three Uses of super

  1. super.variable — access parent class variable
  2. super.method() — call parent class method
  3. super(...) — call parent class constructor (must be the first line)

Example

class Animal {
    String color = "white";
    void eat() { System.out.println("Eating..."); }
}

class Dog extends Animal {
    String color = "black";

    void printColor() {
        System.out.println(color);          // black (own)
        System.out.println(super.color);   // white (parent)
    }

    void eat() {
        super.eat();                    // calls parent method
        System.out.println("Dog is eating");
    }
}

The final keyword is used to restrict the user. It can be applied to variables, methods, and classes — each with a different meaning.

The Three Uses of final

final methodCannot be overridden by subclasses.
final classCannot be inherited (e.g., String).

Example

}

9. Packages

A package is a namespace that organizes a set of related classes and interfaces. It avoids name conflicts and makes large programs easier to maintain.

Two Types of Packages

  • Built-in: Provided by Java — java.util, java.io, java.lang, java.net, java.sql.
  • User-defined: Created by the programmer.

Creating Your Own Package

package mypack;     // must be the FIRST line

public class MyClass {
    public void show() { System.out.println("Hello from mypack"); }
}

Importing a Package

import mypack.MyClass;            // import a single class

    }
}

Advantages

  • Avoids naming conflicts.
  • Provides access control (default access works at package level).
  • Makes code modular and easier to find.
  • Enables code reuse across projects.

Exception Handling Mechanism

Writing programs that don't crash when something goes wrong.

1. Introduction to Exception

An exception is an event that disrupts the normal flow of a program's instructions. Technically, it is an object that the JVM creates and "throws" when something goes wrong at runtime.

Real-Life Analogy

Imagine you're driving to college, but the road is closed. You don't stop forever — you take a detour. Exception handling is the "detour" your program takes when it hits a problem.

Why Handle Exceptions?

  • To prevent the program from crashing abruptly.
  • To give the user a meaningful error message instead of a stack trace.
  • To recover gracefully and continue executing.
  • To separate error-handling code from regular logic.

Example: Without Exception Handling

class Demo {
    public static void main(String[] args) {
        int a = 10, b = 0;
        int c = a / b;             // crashes here
        System.out.println("After division");  // never executes
    }
}

Example: With Exception Handling

class Demo {
    public static void main(String[] args) {
        int a = 10, b = 0;
        try {
            int c = a / b;
        } catch (ArithmeticException e) {
            System.out.println("Cannot divide by zero!");
        }
        System.out.println("After division");  // runs normally
    }
}

2. Exception Hierarchy

All exceptions in Java are descendants of the class java.lang.Throwable. Below Throwable, there are two big branches: Error and Exception.

                Throwable

  • Exceptions = your code can anticipate and recover from them.

3. try & catch

The try block contains code that might throw an exception. The catch block catches and handles it.

Syntax

try {
    // risky code
} catch (ExceptionType e) {
    // handle exception
}

Example: Single catch

try {
    int[] arr = {1, 2, 3};
    System.out.println(arr[10]);
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Index out of range: " + e.getMessage());
}

Example: Multiple catch blocks

try {
    int a = Integer.parseInt("abc");
    int b = 10 / a;
} catch (NumberFormatException e) {
    System.out.println("Invalid number format");
} catch (ArithmeticException e) {
    System.out.println("Math error");
} catch (Exception e) {
    System.out.println("Some other error: " + e);
}
⚠
Order matters!
When using multiple catch blocks, always put the most specific exceptions first and the most general (Exception) last.

4. throw & throws

throw — Explicitly raise an exception

Used inside a method body to manually throw an exception object.

class AgeCheck {
    static void validate(int age) {
        if (age < 18)
            throw new ArithmeticException("Not eligible to vote");
        else
            System.out.println("Welcome to vote");
    }

    public static void main(String[] args) {
        validate(15);
    }
}

throws — Declare possible exceptions

Used in a method signature to inform callers that this method might throw certain exceptions. The caller must then handle or re-declare them.

import java.io.*;

class FileDemo {
    void readFile() throws IOException {
        FileReader fr = new FileReader("data.txt");
    }

    public static void main(String[] args) {
        try {
            new FileDemo().readFile();
        } catch (IOException e) {
            System.out.println("File missing");
        }
    }
}

5. finally Block

The finally block contains code that always executes, whether an exception occurs or not. It's perfect for cleanup code like closing files, releasing locks, or disconnecting from a database.

Example

try {
    int a = 10 / 0;
} catch (ArithmeticException e) {
    System.out.println("Caught: " + e);
} finally {
    System.out.println("Cleanup done — finally always runs");
}

Key Points

  • Runs whether an exception is caught or not.
  • Runs even if a return statement is executed inside try/catch.
  • Only skipped if the JVM exits (e.g., System.exit(0)) or a fatal error.
  • Used mainly for resource cleanup.
🎯
Exam Tip
Always mention that finally is used for resource cleanup.

6. Checked vs Unchecked Exceptions

All exceptions in Java fall into two categories based on when they are detected:

  1. Checked Exceptions — detected at compile-time
  2. Unchecked Exceptions — detected at runtime

1. Checked Exception (Compile-Time)

  • Checked by the compiler at compile-time.
  • Must be either caught with try-catch or declared with throws.
  • If unhandled, the program will not compile.
  • Direct subclasses of Exception (but NOT of RuntimeException).
  • Caused by external factors — file missing, database down, network down.
Common Checked Exceptions
ExceptionCause
IOExceptionInput/output operation failed
FileNotFoundExceptionFile does not exist
SQLExceptionDatabase access error
ClassNotFoundExceptionClass not found at runtime
InterruptedExceptionThread was interrupted
Example: Handling with try-catch
import java.io.*;

class CheckedDemo {
    public static void main(String[] args) {
        try {
            FileReader file = new FileReader("test.txt");
            BufferedReader br = new BufferedReader(file);
            System.out.println(br.readLine());
            br.close();
        } catch (IOException e) {
            System.out.println("File error: " + e.getMessage());
        }
    }
}
Example: Declaring with throws
import java.io.*;

class CheckedDemo2 {
    public static void main(String[] args) throws IOException {
        FileReader file = new FileReader("test.txt");
    }
}

2. Unchecked Exception (Runtime)

  • Not checked by the compiler.
  • Occurs at runtime.
  • Handling is optional — the program compiles successfully even without try-catch.
  • Subclasses of RuntimeException (and Error).
  • Usually due to programming bugs — should be fixed in code, not caught.

File Handling Mechanism

Reading and writing data permanently using files.

1. Introduction to File

A file is a container for storing data permanently on a computer's storage device. In Java, files are used to keep information that should persist even after the program ends.

Why File Handling?

  • Persistent storage — data stays even after the program exits.
  • Data sharing — share information between different programs.
  • Logging — store events, errors, or audit information.
  • Configuration — read app settings from files.

Common File Operations

Create

Make a new file on disk.

Write

Save data into the file.

Read

Get data back from the file.

Delete

Remove the file from disk.

2. java.io Package

The java.io package provides classes for input and output through data streams, serialization, and the file system.

Streams in Java

A stream is a sequence of data. Java has two kinds:

  • Byte streams — handle binary data (images, audio). Classes end with Stream.
  • Character streams — handle text (Unicode). Classes end with Reader or Writer.

3. File Class

The File class (in java.io) is used to represent a file or directory pathname in an abstract way. It does not deal with the contents of the file — only with its metadata (name, size, permissions, existence).

Creating a File Object

File f = new File("test.txt");

}

4. Creating a File

Use createNewFile() to make a new empty file. It returns true if successful, false if the file already exists.

import java.io.*;

class CreateFile {
    public static void main(String[] args) {
        try {
            File f = new File("test.txt");
            if (f.createNewFile())
                System.out.println("File created: " + f.getName());
            else
                System.out.println("File already exists.");
        } catch (IOException e) {
            System.out.println("An error occurred.");
            e.printStackTrace();
        }
    }
}

5. Writing to a File

Use FileWriter to write characters to a file. Always remember to close the stream after writing — otherwise data may not be saved.

import java.io.*;

class WriteFile {
    public static void main(String[] args) {
        try {
            FileWriter fw = new FileWriter("test.txt");
            fw.write("Hello World!\n");
            fw.write("This is Java file handling.");
            fw.close();
            System.out.println("Successfully wrote to the file.");
        } catch (IOException e) {
            System.out.println("Error writing file.");
        }
    }
}
💡
Append Mode
new FileWriter("test.txt", true) opens the file in append mode — new data is added at the end instead of overwriting.

6. Reading from a File

Method 1: Using FileReader (character by character)

import java.io.*;

class ReadFile {
    public static void main(String[] args) {
        try {
            FileReader fr = new FileReader("test.txt");
            int i;
            while ((i = fr.read()) != -1) {
                System.out.print((char) i);
            }
            fr.close();
        } catch (IOException e) {
            System.out.println("Error reading file.");
        }
    }
}

Method 2: Using BufferedReader (line by line — efficient)

import java.io.*;

class ReadFileBuffered {
    public static void main(String[] args) {
        try {
            BufferedReader br = new BufferedReader(new FileReader("test.txt"));
            String line;
            while ((line = br.readLine()) != null) {
                System.out.println(line);
            }
            br.close();
        } catch (IOException e) {
            System.out.println("Error reading file.");
        }
    }
}

7. Deleting a File

Use the delete() method of the File class. It returns true if the file was successfully deleted.

import java.io.*;

class DeleteFile {
    public static void main(String[] args) {
        File f = new File("test.txt");
        if (f.delete())
            System.out.println(f.getName() + " deleted.");
        else
            System.out.println("Failed to delete file.");
    }
}

Complete Program: All 4 Operations

import java.io.*;

class FileDemo {
    public static void main(String[] args) throws IOException {
